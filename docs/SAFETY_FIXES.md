# 存档安全修复说明

日期：2026-11-17，2026-11-26 修订 F6 判据。对应[原始审计](SAFETY_AUDIT.md) F1–F6。

代码整改及独立回归已完成，仍只适合测试副本；实际 ECS 生命周期、保存重载、卸载及 mod 共存验收尚未完成。

## 修改与边界

| 项目 | 实现 | 仍需验证 |
|---|---|---|
| F1 加载缓存 | 城市加载后独立核验所有带目标 policy 的正式线路；关闭 / 1 倍也处理，不依赖 range changed 或超限阈值 | 各种加载路径、同进程切城、新建线路初始化顺序 |
| F2 写入归属 | 保存基线及最后写入值；只接受最后写入值或精确初始值，外部修改触发冲突，不重新捕获已扩容数据作为基线 | 原版车库模式、其他 mod 的实际交互 |
| F3 部分失败 | 先计划和全量预检；异常逆序回滚，包含已写入后抛错的步骤；回滚不覆盖第三方值，并报告是否完整 | Unity 对象销毁等引擎异常场景 |
| F4 容量边界 | 非正基线和乘法溢出直接跳过，不夹到 1 或 int.MaxValue；对全部车库 prefab 的拟议容量做保守总预算检查 | 自定义资产、运行时组合与升级行为 |
| F5 实体边界 | 必须同时有 Route、TransportLine、Policy、RouteModifier；排除 Temp、Deleted、Created；待原版初始化完成后再处理 | 编辑、撤销、删线和加载完成的实际时序 |
| F6 客货用途 | 综合客 / 货线路数据、客货站组件、子对象和升级关系，要求「有客运用途且无货运用途」；用途未知与可重复容量升级不再否决扩容（2026-11-26 修正，见下） | 当前资产的实际组件与使用关系 |

线路实现见 [LineCeilingSystem.cs](../Systems/LineCeilingSystem.cs)，车库实现见 [DepotCapacitySystem.cs](../Systems/DepotCapacitySystem.cs)。
安全写入与筛选规则见 [SafeWriteBatch.cs](../Core/SafeWriteBatch.cs) 和 [DepotSafety.cs](../Core/DepotSafety.cs)。

### 线路缓存的冲突处理

加载后不能无条件用当前 policy 覆盖未知来源的直接缓存修改。
修复版先比较当前缓存是否能由当前范围或本 mod 支持的历史 1–10 倍映射解释；不能解释时，整次线路修改在写入前停止，状态显示冲突。
可以解释的旧缓存会按目标映射重新计算，其他 modifier 槽位和 policy 启用标记保留。

浮点比较存在数值容差，数值相同也无法证明唯一写入者。这是冲突检测的边界，不是排他所有权证明。
若其他 mod 有意直接写 VehicleInterval，即使触发保守冲突也不能靠强行覆盖来解决。

### 车库扩容的范围

7 类交通的线路上限路径保留，但车库扩容仍不覆盖全部 7 类。

判据是「至少一条客运线路或客运站组件到达该设施，且没有任何货运用途到达它」。客货共用的设施跳过，判定依据是客 / 货线路数据、`TransportStation` / `CargoTransportStation` 组件、子对象与升级关系的双向传播。

**2026-11-26 修正**：此前把「仅客运」实现成 `purpose == DepotPurpose.Passenger` 严格相等，`Unknown` 与 `RepeatableUpgrade` 一票否决，结果 34 个候选 prefab 全部跳过、0 个扩容，设置面板却报「已应用」。现在两者只表示「用途未证」与「容量可重复升级」，不再否决写入。

实测分布（34 个候选）：类型不支持 24（`Outside Connection`、`Taxi` 等）、含货运或无客运 4、合格 6。

仍在跳过范围：与货运共用 `TransportType` 的火车场站（如 `RailYard02`）。`Train` 同时被货运线路使用，且该 prefab 不是 `TransportStation`，拿不到客运位；要覆盖必须单设铁路判据，不能退回「按类型放行」。

客货用途向相关子对象和升级关系传播，普通共享装饰物不会把两个无关车站连接成一个用途集合。

容量总预算是针对本次观察到的 prefab 集合的保守防护，不是对任意动态 mod / 非法重复安装升级的无限溢出保证。
若运行时组件改变，后续请求会检测写入冲突并保留外部值；本 mod 不逐帧持续覆盖它。

### 失败处理

普通异常最多尝试 3 次。事务回滚不完整时，本 World 的该系统停止后续应用，设置变更不会解除此阻止；应退出并从未受本次失败影响的副本重新加载。
同步还原返回结果；退出日志会指出还原未完成，不能把进入 OnDispose 当作卸载成功。
两个系统各自执行事务；其中一个失败不表示另一个自动回滚，状态分别显示。

## 默认设置与准备卸载

新设置默认关闭两项功能、倍率均为 1；已存在的设置文件仍会加载原有值。
普通关闭功能保留逐线路 adjustment；只有玩家明确确认“准备卸载”才收回当前城市超限的逐线路设置。

1. 加载测试城市，在本 mod 选项中点击“准备卸载（当前城市）”并确认。
2. 此操作关闭两项功能、设为 1 倍，请求还原受管范围 / 容量并规范当前城市的目标 adjustment。
3. 恢复模拟，等待“线路”和“车库”两项状态都显示“已准备”。冲突、失败或等待均不算完成。
4. 等待实际车辆数按游戏规则收敛，另存测试副本，再退出并移除 mod。
5. 用无本 mod 的环境重载副本，运行、保存、再重载，检查实际车辆、缓存和日志。

此操作只针对当前城市；其他使用过本 mod 的存档需要分别处理。
不直接删除车辆、实体或任何存档文件。“已准备”表示相应数据修改完成，不能代替第 4–5 步的实际验收。
